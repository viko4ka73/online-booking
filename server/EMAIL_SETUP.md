# Письма комплекса «Играем?»

## Подключение Mail.ru

Адрес комплекса: `igraem.spb.booking@mail.ru`.

SMTP-сервер, порт и адрес отправителя задаются в локальном `server/.env`. Отправка включается параметром `MAIL_ENABLED=true` после заполнения пароля приложения.

1. Войдите в почту комплекса. Откройте **Настройки → Все настройки → Безопасность → Пароли для внешних приложений**.
2. Создайте пароль с названием «Играем — бронирования» и доступом **Только отправка писем в Почте**. Для создания такого пароля Mail.ru требует привязанный телефон.
3. Откройте локальный файл `server/.env` и вставьте полученный пароль после `SMTP_PASS=`. Основной пароль почты не используйте. Пароль не отправляйте в чат.
4. Измените `MAIL_ENABLED=false` на `MAIL_ENABLED=true` и сохраните файл.
5. Перезапустите сервер, затем проверьте доставку на своём тестовом бронировании. Перед включением проверьте ожидающие письма в очереди: после подключения сервер начнёт отправлять накопившиеся действительные уведомления.

```dotenv
MAIL_ENABLED=true
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=igraem.spb.booking@mail.ru
SMTP_PASS=пароль_для_внешнего_приложения
SMTP_FROM=igraem.spb.booking@mail.ru
APP_PUBLIC_URL=http://localhost:5173
```

`server/.env` исключён из Git. После публикации замените `APP_PUBLIC_URL` на реальный адрес сайта.

Официальная инструкция Mail.ru: https://help.mail.ru/mail/login/mailer/

## Поведение

- Подтверждение, отмена и перенос создают задания отправки в той же транзакции, что и изменение брони.
- Адрес получателя берётся из актуального профиля непосредственно перед отправкой.
- Напоминание назначается за 24 часа до начала; у записей, созданных менее чем за сутки, отдельного напоминания нет.
- При отмене/переносе прежнее ожидающее напоминание снимается. Для переноса назначается новое, если до нового начала больше суток.
- Пользователь может отключить напоминания; служебные письма об изменении брони остаются включены.
- Очередь хранится в PostgreSQL и переживает перезапуск. При запуске добавляются недостающие напоминания для существующих будущих записей.
- Очередь проверяется каждые 15 секунд, пока сервер работает. На размещённом сайте нужен постоянно работающий сервер.
- При временной ошибке до 8 попыток с увеличением задержки. Письма об изменении брони действительны 7 дней; напоминания не отправляются после начала игры.
- `sent` означает принятие почтовым сервером, а не гарантию попадания во «Входящие». Для надёжности используется постоянный Message-ID, но сбой после SMTP-приёма до фиксации БД теоретически может вызвать повторное письмо.
- Без `MAIL_ENABLED=true` и заполненных SMTP-настроек внешней отправки нет. Сайт прямо показывает это пользователю, а задания остаются в очереди.
- SMS на телефон не подключены: в этой задаче используются электронные письма.

## Логотип в письмах

Во все четыре шаблона встроена PNG-версия логотипа сайта через CID-вложение: загружать картинку с localhost получателю не нужно. Исходник — `client/public/igraem-logo.svg`, экспорт — `server/src/assets/email-logo.png`. При изменении логотипа выполните из папки server `npm run build:email-logo`. Проверка готовых MIME-писем без внешней отправки: `npm run test:email-template`.
